# Документация REST API

## 1. Общая информация

REST API реализован с использованием Django REST Framework.
API позволяет просматривать оборудование, управлять собственными бронированиями, получать историю действий и статистику.
Для всех описанных методов требуется авторизация.
При использовании сессионной авторизации изменяющие запросы требуют CSRF-токен.

Базовый адрес локального сервера:
http://127.0.0.1:8000/

## 2. Оборудование

### GET /api/equipment/

Назначение: получение списка оборудования.
Авторизация: обязательна.

Параметры:
- search — поиск по названию;
- category — фильтрация по категории.

Пример запроса:
GET /api/equipment/?search=мяч

Успех: HTTP 200.

Пример ответа:

```json
[
  {
    "id": 1,
    "name": "Волейбольный мяч",
    "category": "Спорт",
    "total_quantity": 10,
    "available_quantity": 7
  }
]
```

Примечание: значения приведены для примера.

### GET /api/equipment/{id}/

Назначение: просмотр одного оборудования.

Успех: HTTP 200.

Типичные ошибки:
- 401 или 403 — требуется авторизация;
- 404 — оборудование не найдено.

## 3. Бронирования

### GET /api/reservations/

Назначение: просмотр собственных бронирований.
Авторизация: обязательна.

Доступные фильтры:
- status — статус бронирования;
- equipment — идентификатор оборудования.

Пример:
GET /api/reservations/?status=created

Успех: HTTP 200, список бронирований.

### POST /api/reservations/

Назначение: создание нового бронирования.
Авторизация: обязательна.

Тело запроса:

```json
{
  "equipment": 1,
  "quantity": 2
}
```

Успех: HTTP 201.

Пример ответа:

```json
{
  "id": 5,
  "equipment": 1,
  "equipment_name": "Волейбольный мяч",
  "owner": 2,
  "quantity": 2,
  "status": "created",
  "created_at": "2026-11-05T18:00:00Z"
}
```

Значения ответа условные.
Пользователь назначается автоматически.
При создании бронирования сохраняется событие истории.

Типичные ошибки:
- 400 — некорректное количество или оборудование;
- 401/403 — ошибка авторизации.

### GET /api/reservations/{id}/

Назначение: просмотр собственного бронирования.

Успех: HTTP 200.

Ошибка 404 — бронирование не существует или принадлежит другому пользователю.

### PUT /api/reservations/{id}/
### PATCH /api/reservations/{id}/

Назначение: изменение бронирования.
Редактировать можно только бронирование со статусом created.

Пример PATCH-запроса:

```json
{
  "quantity": 3
}
```

Успех: HTTP 200, обновлённый объект.

Типичные ошибки:
- 400 — неправильные данные или запрещённое изменение;
- 404 — бронирование не найдено или недоступно.

### DELETE /api/reservations/{id}/

Назначение: удаление бронирования.

Успех: HTTP 204.

Подтверждённое бронирование удалить нельзя, пока оно не завершено.

Типичные ошибки:
- 400 — запрещено удалять подтверждённую бронь;
- 404 — объект не найден или недоступен.

## 4. Изменение статуса бронирования

### POST /api/reservations/{id}/confirm/

Назначение: подтверждение бронирования.
Тело запроса: не требуется.
Разрешено только для статуса created.

При выполнении:
1. Проверяется текущее состояние бронирования.
2. Проверяется наличие оборудования.
3. Уменьшается доступное количество.
4. Статус изменяется на confirmed.
5. Создаётся событие истории.

Все изменения выполняются внутри транзакции.

Успех: HTTP 200.

Ответ:

```json
{
  "message": "Бронирование подтверждено."
}
```

Типичные ошибки:
- 400 — бронирование нельзя подтвердить;
- 400 — недостаточно оборудования;
- 404 — бронирование недоступно.

### POST /api/reservations/{id}/complete/

Назначение: завершение бронирования.
Тело запроса: не требуется.
Разрешено только для статуса confirmed.

При выполнении:
1. Проверяется статус бронирования.
2. Оборудование возвращается в доступный остаток.
3. Статус изменяется на completed.
4. Создаётся событие истории.

Операция выполняется внутри транзакции.

Успех: HTTP 200.

Ответ:

```json
{
  "message": "Бронирование завершено."
}
```

Типичные ошибки:
- 400 — недопустимый переход состояния;
- 404 — бронирование недоступно.

## 5. История действий

### GET /api/reservations/{id}/history/

Назначение: получение истории бронирования.
Авторизация: обязательна.

Успех: HTTP 200.

Пример ответа:

```json
[
  {
    "id": 10,
    "reservation_id_snapshot": 5,
    "actor_name": "student",
    "action": "Бронирование подтверждено",
    "created_at": "2026-11-05T18:10:00Z"
  }
]
```

Значения условные.
События сортируются от новых к старым.
Ошибка 404 — бронирование не найдено или недоступно.

## 6. Статистика

### GET /api/equipment-statistics/

Назначение: получение статистики оборудования и бронирований.
Авторизация: обязательна.

Успех: HTTP 200.

Пример ответа:

```json
{
  "equipment_types": 3,
  "total_units": 30,
  "available_units": 20,
  "occupied_units": 10,
  "created_count": 2,
  "confirmed_count": 1,
  "completed_count": 4,
  "popular_equipment": [
    {
      "name": "Волейбольный мяч",
      "count": 5
    }
  ]
}
```

Числа приведены для примера.
Статистика количества оборудования формируется по всем записям Equipment.
Статистика бронирований и популярного оборудования рассчитывается по бронированиям текущего пользователя.

## 7. Проверка API

Для проверки используется локальный сервер Django:

    python manage.py runserver

После авторизации можно открыть:
http://127.0.0.1:8000/api/equipment/

Для проверки изменяющих запросов можно использовать интерфейс Django REST Framework или вкладку Network в инструментах разработчика браузера.

При проверке необходимо убедиться, что:
- GET возвращает ожидаемые данные;
- POST создаёт объект;
- запрещённые переходы отклоняются;
- изменения сохраняются в базе данных;
- история операций обновляется.

## 8. Вывод

REST API обеспечивает работу с оборудованием и бронированиями, проверяет авторизацию пользователей и поддерживает историю действий.
Для операций подтверждения, завершения и удаления используются транзакции Django, что обеспечивает согласованность связанных изменений.
