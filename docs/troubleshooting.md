# Типичные ошибки и диагностика

## 1. Не установлен Django

Проблема:

При запуске появляется ошибка:

    ModuleNotFoundError: No module named 'django'

Причина:
Не установлены зависимости или не активировано
виртуальное окружение.

Диагностика:

    python -m pip show Django

Решение:

Активировать виртуальное окружение:

    .\.venv\Scripts\Activate.ps1

Установить зависимости:

    python -m pip install -r requirements.txt

## 2. Отсутствует секретный ключ

Проблема:

При запуске появляется ошибка:

    KeyError: 'DJANGO_SECRET_KEY'

Причина:

Отсутствует переменная DJANGO_SECRET_KEY.

Диагностика:

Проверить наличие файла .env в корне проекта.

Решение:

Скопировать пример конфигурации:

    Copy-Item .env.example .env

Сгенерировать новый ключ Django и записать
его в DJANGO_SECRET_KEY.
Секретный ключ нельзя публиковать.

## 3. Не выполнены миграции

Проблема:

При обращении к базе данных появляется ошибка:

    django.db.utils.OperationalError: no such table

Причина:

Структура базы данных ещё не создана.

Диагностика:

    python manage.py showmigrations

Решение:

    python manage.py migrate

## 4. Не работает авторизация API

Проблема:

При обращении к защищённому API сервер
возвращает HTTP 403 Forbidden.

Причина:

Пользователь не авторизован либо запрос
не прошёл проверку прав доступа.

Диагностика:

Проверить текущего пользователя и ответ сервера.

Решение:

Авторизоваться через страницу:

    /accounts/login/

Повторить запрос к API.
Для изменяющих запросов с сессионной
авторизацией также проверить CSRF-токен.

## 5. Недостаточно оборудования

Проблема:

При подтверждении бронирования появляется ошибка:

    Недостаточно доступного оборудования.

Причина:

Пользователь пытается подтвердить бронирование
на количество, превышающее доступный остаток.

Диагностика:

Проверить поле available_quantity через:

    /api/equipment/

Решение:

Уменьшить количество в бронировании
или выбрать другое оборудование.

## 6. Нельзя выполнить переход состояния

Проблема:

При повторном подтверждении бронирования
возвращается ошибка:

    Подтвердить можно только созданную бронь.

Причина:

Бронирование уже подтверждено или завершено.

Диагностика:

Получить текущее состояние бронирования:

    GET /api/reservations/{id}/

Решение:

Использовать допустимые переходы:

    created -> confirmed -> completed

Завершённое бронирование нельзя
подтвердить повторно.

## 7. Практическая проверка запрещённого перехода

В ходе тестирования было создано и подтверждено
бронирование ноутбука ASUS.
После перехода бронирования в статус confirmed
была выполнена попытка повторного подтверждения.

Запрос:

    POST /api/reservations/1/confirm/

Результат:

    HTTP 400 Bad Request

Сообщение сервера:

    Подтвердить можно только созданную бронь.

Причина ошибки:

Бронирование уже имело статус confirmed.
Повторное подтверждение запрещено логикой приложения.

Вывод:

Система корректно обрабатывает недопустимые
переходы состояния и возвращает сообщение об ошибке.

## Заключение

Для диагностики приложения используются
сообщения Django, HTTP-коды ответов API,
проверка миграций и состояния базы данных.
Документ помогает обнаруживать типичные ошибки
при установке и использовании приложения.
